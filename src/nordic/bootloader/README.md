# DFC open bootloader

Nordic Secure DFU bootloader (nRF5 SDK 16.0.0, `examples/dfu/secure_bootloader/pca10056_s140_ble`) built for the DFC with **signature checking disabled**. It exists so that a DFC owner can flash it once over SWD and from then on update the firmware over the air with nRF Connect, using any build.

This is **not** the bootloader shipped on stock DFC units. The stock one verifies ECDSA P-256 signatures with the upstream developer's key; only packages he signs install on it. A copy of the stock bootloader is kept in `backup_full.hex` at 0xF8000 for reference.

## Flash map (nRF52840, S140 7.0.1)

| Region | Address | Content |
|---|---|---|
| MBR | 0x00000–0x01000 | part of the SoftDevice hex |
| SoftDevice S140 7.0.1 | 0x01000–0x27000 | |
| Application | 0x27000–0xF5000 | linker `LENGTH = 0xCE000` |
| App data (FDS: bonds, settings) | 0xF5000–0xF8000 | 3 pages, preserved across DFU (`NRF_DFU_APP_DATA_AREA_SIZE 12288`) |
| Bootloader | 0xF8000–0xFE000 | this project |
| MBR params page | 0xFE000–0xFF000 | |
| Bootloader settings | 0xFF000–0x100000 | generated by `nrfutil settings generate` |
| UICR NRFFW[0] | 0x10001014 | 0x000F8000 (bootloader start) |
| UICR NRFFW[1] | 0x10001018 | 0x000FE000 (MBR params page) |

## Build

```sh
# once: micro-ecc (the SDK does not ship it)
cd nrf5_sdk/nRF5_SDK_16.0.0_98a08e2/external/micro-ecc
git clone https://github.com/kmackay/micro-ecc.git
make -C nrf52hf_armgcc/armgcc

# bootloader
make -C src/nordic/bootloader -j
python3 src/nordic/bootloader/hexmap.py src/nordic/bootloader/_build/nrf52840_xxaa_s140.hex \
    --flash-max 0xFE000 --expect 0x10001014=0xF8000 --expect 0x10001018=0xFE000
```

The merged image (SoftDevice + bootloader + settings + app) and the DFU packages are produced from `src/nordic/armgcc` with `make merge`, `make dfu_pkg` and `make dfu_pkg_signed`.

`make flash` in `src/nordic/armgcc` programs the merged image over SWD with a chip erase, then restores PSELRESET. Every nrfjprog call runs at 1 MHz (`SWD_KHZ`, default 1000): on the DFC's Tag-Connect footprint the link dropped single bits at 4 MHz and a corrupted UICR write can engage APPROTECT. Read FICR (0x10000000, 256 words) three times first and only flash when all three match. If the erase fails while the board is reset-looping, `nrfjprog --recover` first.

## Files

`Makefile`, `secure_bootloader_gcc_nrf52.ld`, `sdk_config.h`, `main.c` and `nrf_crypto_allocator.h` are copies of the SDK example (`examples/dfu/secure_bootloader/` and its `pca10056_s140_ble` variant) with the paths pointed at `nrf5_sdk/`, the overrides below appended to `sdk_config.h`, and `-Wno-error=array-bounds` added because GCC 12+ flags SDK 16 code. `hexmap.py` checks an Intel-HEX footprint.

## Keys

`keys/dfc_open_dfu_private.pem` and the derived `keys/dfu_public_key.c` are committed **on purpose**. The bootloader does not require signatures (`NRF_DFU_REQUIRE_SIGNED_APP_UPDATE 0`), so the key only matters for people who prefer to sign packages anyway; it protects nothing. Never reuse it for a bootloader that does enforce signatures.

## Configuration deltas vs the SDK example

| Setting | Value | Why |
|---|---|---|
| `NRF_DFU_REQUIRE_SIGNED_APP_UPDATE` | 0 | open bootloader |
| `NRF_DFU_BLE_ADV_NAME` | "DfuTarg" | nRF Connect auto-selects it |
| `NRF_DFU_APP_DATA_AREA_SIZE` | 12288 | matches the app's 3 FDS pages |
| `NRF_BL_DFU_INACTIVITY_TIMEOUT_MS` | 120000 | leaves DFU mode after 2 min idle |
| DFU entry | buttonless only | the DFC has no button; the reset pin is remapped by the flashing recipe |

Prefer doing a DFU with the bike cable unplugged: while the bootloader runs the SP3222 control pins float. (One update on 2026-10-14 was done with the cable attached and the bike idle without any visible effect on the tablet; not a guarantee.)
